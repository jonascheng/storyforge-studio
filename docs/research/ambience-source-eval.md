# 內建零花費環境音庫技術評估：純演算法合成 vs CC0 音訊檔打包

評估針對 StoryForge 有聲書加入「場景持續環境音（Scene Ambience）」之兩種零花費、純本機實作路徑。

---

## 1. 核心評估維度

| 維度 | 方案 A：純數學合成（numpy/scipy 演算法） | 方案 B：輕量 CC0 循環音訊檔打包（推薦） |
|---|---|---|
| **聲音真實度** | 風聲/雨聲堪用；鳥鳴/蟲鳴/壁爐極難寫出自然細節 | 100% 真實錄音，質感達商業有聲書標準 |
| **依賴與安裝體積** | 需新增 `scipy` + `numpy`，套件體積增加 ~60 MB | 0 新增套件依賴；8 款音檔僅增加 ~600 KB |
| **啟動與執行效能** | 每次需 CPU 即時計算波形，啟動慢 | `pydub` 直接載入 MP3，毫秒級讀取 |
| **循環接縫平滑度** | 需自寫帶通濾波器與循環包絡 | 現有 `_build_looped_bgm` crossfade 直接沿用 |
| **五歲小孩比喻** | 用嘴巴跟雙手模仿風聲與拍桌聲 | 玩具盒子裡直接附 6 顆真實錄音小按鈕 |

---

## 2. 深入分析

### 方案 A：純數學演算法合成（如 `lemo-opuscar`）
* **原理**：用隨機雜訊（白噪音/布朗噪音）配合帶通濾波器模擬風雨聲。
* **致命痛點**：
  1. StoryForge 目前沒有引入 `numpy` 與 `scipy`。引入 `scipy` 會讓 `uvx storyforge-studio` 的首次下載時間顯著拉長（約 60MB 的 wheel 包）。
  2. 複雜環境（如真實森林鳥鳴、夏夜蟋蟀、咖啡廳低語）純數學公式無法產生真實質感，聲音容易帶有廉價電子合成感。

### 方案 B：輕量 CC0 循環音訊檔打包（推薦方案）
* **原理**：精選 6～8 款高頻使用之 CC0 自然環境音（雨聲 rain, 風聲 wind, 森林鳥鳴 forest, 壁爐 fireplace, 夜晚夜蟲 night, 房間日常 room），每段 10 秒。
* **規格優勢**：
  1. 壓縮為 64kbps mono MP3，單檔僅約 80 KB。全套 8 款總體積 < 650 KB。
  2. 現有專案已配備 `pydub` 與 `static-ffmpeg`，完全不需增加任何 Python 相依套件。
  3. 循環邏輯可完全復用現有 `_build_looped_bgm` 的 1 秒 crossfade 演算法，聲音絲滑無卡頓。

---

## 3. 建議決議

採納 **方案 B：輕量 CC0 循環音訊檔打包**。
於 `infrastructure/resources/ambience/` 存放打包音檔，並透過 `AmbienceCatalog` 統一管理讀取與循環。
