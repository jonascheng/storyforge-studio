# ADR 0001 — 以場景為單位的語音生成流程

**日期**：2026-09-10  
**狀態**：已確認

---

## 背景

StoryForge 需要將一篇文字故事轉換為有聲書成品。最直觀的做法是把整篇故事一次丟給語音模型，但這樣有明顯的缺點：使用者只要修改一個字，就必須重跑整篇，耗時又浪費費用。

## 決定

採用**以場景（Scene）為單位的語音生成流程**：

```
故事原稿
  ↓
AI 導演 — 劇本拆解（拆成場景 + 台詞行 + 聲音導演備註）
  ↓
場景 1 → 每行台詞逐行呼叫 TTS → 場景音檔 scene_01.mp3
場景 2 → 每行台詞逐行呼叫 TTS → 場景音檔 scene_02.mp3
  ...
  ↓
聲音拼接 → final_output.mp3
```

具體規則：
1. **AI 導演一次完成兩件事**：拆台詞行 + 自動切場景 + 為每行台詞寫聲音導演備註
2. **切場景標準**：時間地點轉換或情緒基調轉換都算分界點，每場景最多 300 字保底
3. **每行台詞單獨呼叫 TTS**：角色數量無上限，每行精確控制聲音導演備註
4. **場景音檔立刻存磁碟**：存為 ~/Documents/StoryForge/<故事名稱>/scene_NN.mp3
5. **重生成最小單位是場景**：使用者只改了場景 2，只重跑場景 2，其餘沿用
6. **重生成直接覆蓋舊檔**：不保留備份版本
7. **音檔拼接使用 pydub**：不依賴外部工具（無需使用者安裝 ffmpeg）
8. **角色聲音對應表存於故事資料夾**：voice_map.json，由 AI 初步建議，使用者可修改

## 被放棄的替代方案

| 方案 | 為何放棄 |
|------|---------|
| 整篇一次 TTS | 修改任何一處都要全部重跑，耗時且浪費費用 |
| 每行台詞獨立存音檔（不合併成場景） | 粒度太細，使用者難以感知「這一段改好了」 |
| 用 ffmpeg 拼接 | 需要使用者額外安裝軟體，增加設定門檻 |
| TTS 用情緒對照表（「開心」→ [cheerful]） | 彈性不足，AI 直接生成聲音導演備註更準確 |

## 代價

- 呼叫 TTS 次數 = 台詞行數，比一次性呼叫費用高
- 場景內的音檔是逐行拼接，角色換場時可能有輕微節奏感差異

這些代價在第一版可接受。若未來費用是瓶頸，可考慮將同場景同角色的連續台詞合批。

---

## 同時決定的實作細節

- SDK 從 google.generativeai（已棄用）換成 google.genai
- AI 導演模型：gemini-3.8-flash（劇本拆解）+ gemini-3.1-flash-tts-preview（語音生成）
- 使用者自行命名故事，資料夾以故事名稱建立
- AI 自動為每個場景取標題，供使用者在劇本編輯區識別
- 使用者可刪除場景，第一版不做拖拉排序
