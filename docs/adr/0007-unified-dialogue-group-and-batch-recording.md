# ADR 0007 — 取消旁白特例與統一整組朗讀（雙角合奏與單人批次）

**日期**：2026-09-16  
**狀態**：已確認

---

## 背景

在 ADR 0002 中，原先規劃說書人（旁白）視同普通說話角色，可與任一角色搭檔合奏。然而在後續實作（提交 `bf8fc589`）中，考量旁白為情境敘述，為防與角色對話語氣混淆，引入了 `type_changed = is_narration != current_is_narration` 隔離邏輯，將旁白強制獨立成組。

這項隔離引發了顯著副作用：
1. **碎片化呼叫激增**：在旁白與角色穿插交替的有聲書常見情境下，旁白頻繁落單成組。
2. **單人組逐句呼叫負擔**：先前實作中，組內若僅有 1 位角色（如純旁白段落），系統退回逐行發送 API，導致 API 往返趟數劇增，極易觸發每分鐘呼叫額度上限（429 限制），拉長有聲書生成時間。

## 決定

取消旁白隔離特例，全面升級為**統一朗讀對話組與整組朗讀機制**：

1. **消除旁白隔離特例（貪婪分組）**：
   - 移除 `type_changed` 邏輯。說書人（旁白）回歸與一般角色相同的分組待遇。
   - 依台詞順序貪婪掃描，只要累計角色不超過 2 位（如「旁白 + 角色A」或「角色A + 角色B」）、句數不超過 6 句、字數不超過 300 字，即歸入同一朗讀對話組。
2. **單人朗讀組整組批次朗讀**：
   - 當組內只有 1 位角色（純連續旁白或單一角色獨白），不再逐句單獨呼叫 API，而是將整組台詞一次送交大腦演繹為單一音訊片段，徹底消滅單行碎片。
3. **說書人專屬導演引導（防語氣對聊化）**：
   - 在提示詞中針對說書人提供專屬指引：標註為「冷靜沉穩的第三方說書人（Calm and steady third-person narrator）」，並於提示詞明訂「說書人負責背景敘事，角色負責對白演出」，避免大腦誤將旁白演繹成角色的對聊夥伴。
4. **組內呼吸停頓由大腦自然發揮**：
   - 組內旁白與角色交替由語音模型依標點符號自然換氣過渡；組與組之間維持 300ms 靜音間隔。
5. **安全與容錯降級保全**：
   - 若合奏或整組朗讀因安全審查或異常失敗，自動降級為逐句單行錄音備案，確保有聲書順利產出。

## 被放棄的替代方案

| 方案 | 為何放棄 |
|------|---------|
| 維持旁白強制隔離 | 造成大量碎片化呼叫，生成速度緩慢且浪費額度 |
| 僅雙角色合奏，單人組維持逐句錄音 | 純旁白為主的場景無法享受批次效益 |
| 在提示詞中硬性規定停頓秒數 | 易導致語調死板機械，破壞大腦演繹的自然流暢度 |

## 代價與收益

- **收益**：API 呼叫次數大幅減少（預期再省 40%～60%），大幅加快生成速度並降低 429 額度超限風險。
- **代價**：提示詞建構需精細區分說書人與對話角色；需更新分組邏輯相關之單元測試驗證。
